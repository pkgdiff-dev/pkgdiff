About {{ appName }}

Every release note between two versions of a package, with a security picture of the upgrade.

Who runs it

{{ appName }} is built and operated by {{ operatorName }}, an individual developer. It is free to use and needs no account. The code is on GitHub, where you can report a problem. You can also write to {{ contactEmail }} or find {{ operatorName }} on GitHub.

Where the data comes from

Versions and package details come from the registries: NuGet, npm, PyPI, Maven Central, pub.dev and Packagist. Release notes come from those registries and from each project's GitHub releases and changelogs. Every note links back to its source, and it still belongs to its authors.

The security information comes from these services:

  • OSV.dev for known vulnerabilities
  • deps.dev for package and project information
  • OpenSSF Scorecard for project security practices
  • Socket for suspicious package behaviour

How changes are categorised

Changes are sorted into groups such as breaking changes, new features and bug fixes by matching the section headings and keywords in the release notes. These are rules, not a reading of the code, so a change can land in the wrong group, and a breaking change its authors did not mention will not appear.

How fresh the data is

Package data is stored and refreshed by background jobs, so a very recent release or advisory can take time to appear. Security checks run in the background too, and a page shows what was last retrieved.

What it cannot tell you

No listed vulnerability does not prove a package is safe. It means the sources above report nothing for it right now. Use {{ appName }} to prepare an upgrade, and still test the upgrade yourself. The release digests are written by AI and not reviewed by a person, so they are labelled as such and kept out of search results.
